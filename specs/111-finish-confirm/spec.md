# Spec 111: 완료 재확인 게이트 (`OMK_FINISH_CONFIRM`) — 초안

상태: 초안(PR #230) · 기본값 off · 작성 2026-10-22 KST

## 1. 문제
모델이 첫 번째 "완료" 선언을 하면 바로 종료돼요. 검증이 덜 된 상태로 채점되는 실패가 생길 수 있어요. 이건 가설이고, 이 실패의 빈도는 아직 잰 적이 없어요.

## 2. 변경 (플래그 on일 때만)
1. 런에서 처음 완료를 선언하면 바로 종료하지 않아요. 대신 확인 메시지를 한 번 주입해요.
   - 확인 메시지 내용: 현재 워크스페이스와 터미널 상태 요약(최근 명령 출력 꼬리, `git status --short` 요약. 워크스페이스가 git 저장소가 아니면 `git status` 요약은 빼고 나머지만 보여 줘요), 그리고 "채점되면 더 고칠 수 없어요. 확실하면 다시 완료를 선언하세요."
2. 그다음 완료 선언이 나오면 무조건 종료해요.
3. **런당 확인은 최대 1회로 강제해요.** 확인 뒤에 모델이 작업을 이어 가다가 다시 완료를 선언해도 다시 묻지 않아요.
   - 카운터는 런(실행) 단위예요. compaction이나 재시도가 있어도 초기화되지 않아요.
   - Terminus 2는 다시 물을 수 있어요. 확인 응답에서 완료를 다시 표시하지 않으면 `_pending_completion`이 False로 돌아가기 때문이에요(L1624). 이 점이 Terminus 2와 달라요.
4. 확인 단계도 기존 턴, 시간, 토큰 예산 안에서 써요. 예산을 늘리지 않아요.

## 4. 테스트 (단위 테스트, 유료 실행 없이)
- off: 완료를 선언하면 바로 종료해요. 기존 동작과 바이트 단위로 같아야 해요.
- on: 첫 완료 → 확인 메시지 1회 → 두 번째 완료 → 종료.
- **무한 반복 방지**: 모델이 매 턴 완료를 선언하는 가짜 모델에서 확인 메시지가 정확히 1회만 나와야 하고, 종료까지 걸리는 턴은 2턴 이하여야 해요.
- 확인 뒤에 작업 → 다시 완료: 추가 확인 없이 종료해요.
- 완료를 선언하지 않은 채 예산이 끝나면 기존 종료 경로를 그대로 타요.
- **compaction/재시도 뒤에도 1회 제한 유지**: 확인 1회 후 compaction 또는 재시도가 일어나고 다시 완료를 선언하면, 추가 확인 없이 종료해요.
- **git 저장소가 아닌 워크스페이스**: 확인 메시지에 `git status` 요약이 없고, 오류 없이 정상적으로 완료·종료해요.

## 5. 사전등록 판정 (pilot 전에 고정, 변경 불가)
- 설계: 같은 모델, 같은 effort로 off/on을 짝지어 비교해요. 분석 단위는 작업 클러스터예요(cluster bootstrap 또는 GEE).
- **비열등성**: 해결률/accuracy 차이(on − off)의 작업 클러스터 95% CI 하한이 **−3점보다 커야** PASS예요.
- 가드레일: **작업당 총 토큰** ≤ 1.10x, 실행 시간 ≤ 1.25x
  - 턴당 토큰이 아니라 작업당 총 토큰으로 재요. 이 기능은 턴을 늘리니까 턴당으로 재면 늘어난 비용이 가려지기 때문이에요.
- pilot
  - **TB 4.0에서만** 돌려요. `PILOT_N = 180` (작업 30개 × OFF/ON 2 arm × 3회, 총합). 내부 89개 세트는 pilot이 없어요.
  - pilot 작업은 TB 4.0 본 측정 세트에서 무작위로 30개를 뽑지만 실행은 따로 해요. 본 측정 작업 수(66개)는 그대로예요.
  - 본 측정의 작업당 반복 수 n은 pilot에서 잰 분산의 단측 80% 상한으로 정하고, TB 규칙상 하한인 `MIN_TRIALS_PER_TASK=5` 이상이어야 하며 본 측정 시작 전에 고정한다. 이 n으로도 작업 군집 95% CI 하한이 −3점을 넘을 수 없다고 계산되면 본 측정은 돌리지 않고 '판정 불가'로 기록한다. n은 본 측정 중에 바꾸지 않는다.
  - pilot은 ρ와 분산 추정에만 써요. pilot 데이터는 판정에서 빼요.
  - 주의: 같은 작업 반복 결과의 상관이 ρ ≥ 0.3이면 유효 표본이 TB 약 220개에서 막혀서 "판정 불가"가 나올 가능성이 커요. ρ는 가정값이고 pilot에서 확인해요.
  - 무료 실행 한도나 금액 한도로 그 n에 닿을 수 없을 때도 본 측정 전에 **"판정 불가(inconclusive)"**로 spec에 커밋하고 본 측정은 돌리지 않아요.
- **실행 조건**: 측정 순서는 spec 107 다음 111이에요. 무료 실행 한도가 확인되거나 인호님이 금액 한도를 정하기 전에는 pilot을 포함한 어떤 유료 실행도 시작하지 않아요.
- **기본값을 켜는 건 별도 spec으로만** 해요. 이 spec으로는 PASS가 나와도 옵트인 상태로 둬요.
