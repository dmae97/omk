# Request admission, recall selection and control deadlines

This change is based on `935b4882763feb1da46e5f8ccaef05624190b135`. It preserves producer-owned compaction and stream settlement, and adds a bounded logical-request admission layer to the existing `SessionRunBudget` wrapper.

`OMK_REQUEST_ADMISSION_MODE=observe` is the default. `enforce` refuses locally estimated oversized or malformed requests before logical dispatch; `off` disables this inspection. The JSON projection has cumulative length, node and depth bounds before building owned strings. This is not a final provider-wire, HTTP-attempt or billing guarantee. Exact model token accounting remains provider-specific.

`OMK_VERIFIED_MEMORY=1` keeps the existing explicit memory opt-in. A recall now shares at most eight source snapshots inside one call, rechecks current file metadata and rechecks expiry/revocation after source verification. No snapshot is retained across model requests. The source schema, trust policy and exact quote semantics are unchanged.

`OMK_MEMORY_SELECTION=legacy` remains the default. `v2` uses lexical query coverage, diminishing term utility and complete-span redundancy suppression. Each proposed selection prices the actual synthetic tool pair and passes a full-context fit callback; rejected candidates do not automatically discard later feasible items. Empty or non-overlapping queries select no quotes. The synthetic pair uses deterministic identifiers and timestamp zero, and is never an execution receipt. This heuristic is not a semantic retrieval system or optimal knapsack.

Local session control retains its authorization, duplicate-request and private-socket checks. It additionally enforces a total monotonic connection lifetime, default 10 seconds, independent of idle activity. The low-level `startSessionControl(session, { requestTimeoutMs })` accepts a positive bounded duration. Client and server recheck time at response/admission boundaries rather than relying solely on timer callback order. An expired connection does not prove the accepted prompt stopped, and unknown outcomes must not be automatically retried.

Control aborts no longer share the mutating-command budget. Each admitted `prompt` command advances a server-side generation counter exposed through `status.state.generation`; `abort` may carry that exact `generation` and is refused when it does not match the current one. Aborts without a generation are honored only while no abort has already consumed the current generation, and every abort request id is remembered in a bounded 256-entry ledger. These checks run before the 1024-entry mutating cap, so exhausting prompt admission can no longer make a running prompt unabortable. The ledger bound is a known limit: an evicted frame is indistinguishable from a fresh cancellation intent, and only an explicit generation closes that window. `ABORT accepted` still means cancellation was acknowledged, never that the prompt stopped.

`OMK_EVAL_TRACE` remains an explicit absolute NEW file path for a single prompt scope. A second scope requires a different path or no trace. Trace terminal failures do not retain an already-settled logical request. Hash chaining is corruption detection, not same-user tamper resistance or billing attestation.

Focused repository tests are `phase5-admission-json`, `phase5-memory-score`, `phase5-memory-source`, `phase5-memory-selection`, `phase5-control-deadline`, `phase5-budget-lifecycle`, `phase5-native-lifecycle` (real `AgentSession`, compaction commit and shutdown receipt) and `session-control-abort-window` (cap bypass, generation binding, bounded abort ledger). The delivered audit bundle ran separate Node tests with named dependency seams; these repository tests, full monorepo checks, actual providers and non-Linux hosts still require verification on the supported toolchain.
