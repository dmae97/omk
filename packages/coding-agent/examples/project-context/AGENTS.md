# Project Agent Guide

Use this file for repository-specific commands and operating rules. Keep the durable product and delivery context in the companion documents instead of duplicating it here.

## Read before work

- `PRD.md`: what to build, who it serves, and what is out of scope.
- `ARCHITECTURE.md`: stack, folder ownership, interfaces, and data flow.
- `DESIGN.md`: visual language, components, accessibility, and interaction intent.
- `RULES.md`: coding style, safety boundaries, and prohibited actions.
- `TASKS.md`: the next small step and its acceptance condition.
- `PROGRESS.md`: verified outcomes, known failures, and the current next step.

## Working agreement

1. Work on one `TASKS.md` item at a time and preserve unrelated user changes.
2. Follow `RULES.md` and existing project conventions before introducing a new pattern.
3. Run the acceptance check for the active item and record the exact result in `PROGRESS.md`.
4. Update `TASKS.md` and `PROGRESS.md` with facts, not planned or unverified completion claims.
5. Keep these documents current when requirements, architecture, design, or scope change.
